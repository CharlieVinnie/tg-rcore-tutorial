# VirtIO Block 设备驱动开发规程

本文档旨在记录基于 RISC-V 架构 Supervisor（S 态）模式实现最小化 `virtio-blk` 块设备驱动的完整开发流程，涵盖功能模块划分、核心机制设计、体系结构适配特征以及调试与缺陷修复记录。

## 1. 模块划分与设计思路

构建 VirtIO 设备驱动的核心在于确立软硬件间的通信语义与内存屏障规范。本驱动的构建主要分解为以下阶段：

- **执行环境初始化**：基于 `tg-sbi` 与第一章（ch1）的基础设施，建立 `#![no_std]` 的独立运行环境，并实现串口输出及基础物理页面分配器（基于静态数组的 DMA 分配器）。
- **设备发现（Device Discovery）**：解析底层传递的展平设备树（FDT，Flattened Device Tree），遍历内存映射区间，寻址包含 `"virtio,mmio"` 兼容性标识且 Device ID 为 `2` （块设备）、Magic 字段校验为 `"virt"` 的节点。
- **设备初始化序列**：严格依据 VirtIO 规范的 7 步状态机推进设备初始化（复位、确认、驱动探测、特性协商、特性确认、队列配置、驱动就绪）。
- **虚拟队列（VirtQueue）配置**：于物理内存中分配连续页帧，依次划定描述符表（Descriptor Table）、可用环（Available Ring）与已用环（Used Ring）的内存编址。
- **协议实现与阻塞轮询**：将读写请求抽象为三段链式描述符（请求头、数据缓冲区、状态字），实现描述符入队（Enqueue）与设备响应轮询（wait_for_used）的阻塞机制。

## 2. 具体实现细节与架构适配

### 静态内存划分与抽象精简
多数现代操作系统利用高级生命周期管理与页表映射实现 VirtQueue 的动态分配。出于教育视角与机制简化的考量，本驱动采用静态连续内存划分机制：
- 预先定义物理地址对齐的静态缓冲区 `static mut DMA_BUF`，用以承载所有环状队列结构与数据流通。

### MMIO 规范版本差异的适配（Legacy / V1）
在驱动实现过程中，识别设备模拟版本至关重要。QEMU 的 `virt` 平台默认提供遵循 **Legacy MMIO (VirtIO Version 1)** 规范的设备模拟。
- **架构差异**：VirtIO V2 标准中允许分别向特定寄存器（`0x80`, `0x90`, `0xa0`）写入三大队列表的物理地址。而在 Legacy V1 规范中，VirtQueue 被要求在物理内存中强制连续，通过向 `QueuePFN` (`0x040`) 寄存器写入该连续段首地址的页帧号进行统一配置。
- **地址演算机制**：基于 Legacy V1 的约束，驱动需静态计算可用环与已用环相对基址的偏移量。由于设定的 QueueSize = 16，根据规范公式，三者之间须通过页面对齐（4096 字节）来确保外设 DMA 寻址的准确性。

## 3. 调试过程与缺陷分析

**缺陷描述：QEMU 发生内部陷入死锁**
在完成读写扇区函数并向 `QueueNotify` 发送指令以唤醒设备后，驱动长时间停滞于 `wait_for_used` 的轮询检测中。设备未返回完成状态，并最终导致 QEMU 抛出超时退出信号。

**排查与分析**：
1. 初始排查集中于 RISC-V 的 `fence` 内存屏障指令，怀疑因内存乱序导致设备未能读取至可用环的变化。添加追踪日志后证实，寄存器与队列内存确已落盘。
2. 经查阅相关参考实现与 QEMU 源码，确认缺失了对关键硬件特性寄存器 `GuestPageSize (0x028)` 的初始化赋值。

**根因辨识与修复**：
- 根据 Legacy V1 规范，即便驱动程序向 `QueuePFN` 正确交付了物理页帧号，若未预先通过 `GuestPageSize` 寄存器通知设备目标操作系统的页大小（本例中为 4096 字节），外设的 DMA 控制器将无法依据默认算法计算可用环与已用环的基地址。这必然引发越界访问或静默的硬件状态机死锁。
- **修复方案**：在特性协商阶段完成后，向 `0x028` 寄存器写入硬性规定值 `4096`。修正后，读写环形队列可正常流转并收发响应。

## 4. 总结与规范化改进

后续重构中，移除了源码中直接使用的十六进制立即数（Magic Numbers），统一替换为语义明确的规范常量（例如 `VIRTIO_REG_*` 与 `VIRTIO_STATUS_*`）。这不仅提供了一个极简、无外部依赖的块设备驱动实现，同时也清晰展现了 VirtIO 虚拟化标准在底层状态同步机层面的历史架构特性。
