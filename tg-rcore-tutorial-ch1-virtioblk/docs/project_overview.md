# VirtIO Block 设备驱动概览

本项目于 RISC-V 架构及 QEMU 模拟器环境中，以严格满足 `#![no_std]` 及裸机（Bare-metal）限制条件的代码规模，演示了基础设备驱动程序的完整构建链路。项目详细呈现了内核级程序从底层硬件寄存器操控直至顶层虚拟块设备（Virtual Block Device）读写的交互标准。

## 1. 核心功能实现

本驱动实现为一最小化的操作系统级设备驱动教学模型，包含了如下功能模块：
1. **基于设备树的硬件解析**：实现独立的展平设备树（FDT）节点解析，自主挂载并寻址位于内存映射区间（MMIO）的外设基址。
2. **硬件状态机的协议握手**：严格遵循 VirtIO 规范完成外围总线的握手确认序列（包含设备复位、协议版本确认及功能特性协商）。
3. **基于共享内存的虚拟队列模型**：摒弃外部高层封装库，运用底层寄存器抽象并在物理内存中显式构建虚拟队列布局（Descriptor Table、Available Ring、Used Ring），实现处理器与外设控制器的主客体资源同步。
4. **扇区级 I/O 调度**：构建同步的 `read_sector` 与 `write_sector` 接口，支持以扇区（Sector，512 字节）为基本单位进行数据块的完整写入与回读。

## 2. 架构设计与执行流图

系统执行依托于 Supervisor 态（S 态）。经由 `OpenSBI` 交接控制权后，核心执行流如下所示：

### 阶段一：运行环境与内存引导
`_start` 汇编入口布置 `16 * 4096` 字节的栈空间并转入 `rust_main` 高级语言入口。
在环境内部，为了承载与块设备异步交互的数据缓冲区与消息队列，系统构造了极简的 DMA 控制器：通过预留的全局物理数组（`DMA_BUF`）及其内部游标，实现了基于页面对齐的物理连续内存分配，使得外设通过 DMA 进行请求访问时安全可靠。

### 阶段二：设备寻址（Device Discovery）
由于 RISC-V 体系的外围设备位置具有动态特性，`rust_main` 将接收自底层固件在寄存器中传递的 FDT 物理地址。
引导程序通过解析设备树，查找兼容性（`compatible`）包含 `"virtio,mmio"` 属性的节点。当校验节点首地址内 12 字节中符合 `Magic=0x74726976("virt")` 且 `DeviceID=2` 两个条件时，即明确锁定目标 VirtIO 块设备。

### 阶段三：控制流接管与协议联络
设备寻址成功后，执行 `VirtioBlock::init()` 系统初始化。
CPU 通过向基址偏移为 `0x070` 等地址写入预定状态信息（RESET、ACKNOWLEDGE、DRIVER），建立与外设的双向确认。
其最核心步骤在于设备队列配置：驱动在获取的物理连续空间内，依循 Legacy (VirtIO V1) 标准，将内存分段分配给描述符区域（Descriptor Area）、可用环区域（Available Ring）以及已用环区域（Used Ring），并最后将对应的页帧号（PFN）写回给硬件控制器。写入 `DRIVER_OK` 后，硬件设备正式激活。

### 阶段四：I/O 读写周期调度
核心验证测试旨在将特定载荷（如 `"Hello World!"`）写入虚拟第 0 扇区。交互周期可概括为：
1. **描述符装载**：分配请求结构。以三段联动结构表示一次 I/O：请求指示位（`VirtioBlkReq`，指明类型和扇区段） → 数据有效载荷缓冲区段 → 状态应答字字段。
2. **作业提交**：将结构化描述符加入可用环（Available Ring）中标记待处理序号，并对位于偏移 `0x050`（`QueueNotify`）的寄存器进行写操作，从而向设备中断控制器触发执行请求。
3. **阻塞轮询（Wait-for-used）**：CPU 转入 `wait_for_used()` 阻塞函数。借由内联汇编等手段执行空指令轮询，监控共享内存区域中已用环（Used Ring）计数器的更新，直至设备显式填充完成信号。
4. **验证恢复**：从控制块中提取应答成功标志，拆卸装载内存。依序构造读操作（Read）描述符重现相同机制以检索载荷数据，最终完成一致性校验并在控制台予以输出。

## 3. 设计总结
此工程将繁杂的操作系统架构裁剪至最薄层。抛开庞大且层次冗余的系统抽象包裹，向受众揭示了以共享环状缓冲及寄存器写入为代表的底层 CPU 控制逻辑。该实现是透析硬件级虚拟化（Hardware-level Virtualization）协议与现代异步外设执行本质的基础范式。
