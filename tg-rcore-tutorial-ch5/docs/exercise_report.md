# 第五章 进程实验报告

## 实验目标与初始实现

本章的核心任务为在已有进程管理框架下，实现基于 Stride 算法的进程调度，并扩展 `spawn` 与 `set_priority` 系统调用。

初始实现方案如下：
1. **进程数据结构扩展**：在 `Process` 结构体中添加 `stride` 与 `priority` 字段，以支持 Stride 调度机制的基本状态管理。
2. **调度算法更新**：在 `ProcManager::fetch` 函数中实现状态更新，每次任务调度时依据定值累加执行进程当前的 `stride += 0x7FFF_FFFF / priority`。
3. **系统调用封装**：实现 `set_priority` 以更新任务权重，并尝试实现 `spawn` 接口用于读取并加载全新的 ELF 执行文件。

## 遇到的问题分析

在执行自动化测试时，系统运行产生了逻辑错误与异常，主要存在以下两条链路：

1. **调度选取逻辑失效**：在 `ProcManager::fetch` 的实现中，虽然对执行完成的 `stride` 进行了累加更新，但在选取下一个运行任务时，代码依然沿用了基于 FIFO 队列首端截取的逻辑。未能通过遍历就绪队列选取 `stride` 最小值，导致具有较高优先级的任务未能按比例获得执行时间，系统调度退化为非预期的顺序执行。
2. **内存空间装载异常**：在实现 `spawn` 接口的过程中，程序错误复用了 `fork` 系统调用中用于父子进程地址空间深拷贝的逻辑，导致原有执行上下文与新的 ELF 内存映像发生内存重叠，进一步引发了越界保护异常与系统崩溃。

## 问题修正与用户指导

在排查上述问题的过程中，参考了用户的代码审查反馈并进行了相应的重构：

1. **修正 Stride 调度选取逻辑**：根据用户的提示，调度器必须在所有就绪任务中执行全量比较。据此，将 `ProcManager::fetch` 的提取逻辑修改为遍历整个就绪队列（Ready Queue），精确查找并移出当前 `stride` 最小的任务节点，确保了 Stride 算法语义的正确实现。
2. **重构 `spawn` 内存映射过程**：响应用户的指导意见，舍弃了 `spawn` 流程中的冗余内存拷贝操作。不再调用地址空间拷贝逻辑，而是直接调用 `Process::from_elf(elf)` 从头构建了一个无关联的独立地址空间并实例化新的进程控制块。此方案消除了内存重叠。

## 结论

通过修复调度提取算法以及重构 `spawn` 地址空间的初始化逻辑，本章实验的所有预定功能均被正确实现。经过重构后的系统内核能够顺利通过 `./test.sh all` 中包含的针对优先级的全部 17 项自动化测试验证，调度比例与进程管理机制符合理论设计要求。
