# 第六章 文件系统与系统调用移植实验报告

## 实验目标与初始实现策略

本章节的核心任务是在引入 `easy-fs` 文件系统框架的基础之上，完成 `linkat`（硬链接创建）、`unlinkat`（解除硬链接）以及 `fstat`（文件状态获取）三个文件管理相关系统调用的实现；同时，需将第四章、第五章中已实现的 `mmap`、`munmap` 和 `spawn` 系统调用平滑移植至当前的执行架构中。

初始阶段的任务实现策略如下：
1. **文件系统接口实现**：针对硬链接需求，在 `easy-fs` 底层的 `DiskInode` 结构中维护 `nlink`（引用计数）字段。创建硬链接时增加计数，并在目录项中新增该 Inode 的记录；解除链接时递减该计数，并在引用归零时执行磁盘数据块与节点资源的回收。针对 `fstat`，构建内核层面的 `Stat` 数据结构以准确向用户空间返回文件的 `inode_id`、`mode` 及硬链接数等物理特征属性。
2. **内存与进程控制系统调用移植**：在 `sys_mmap`、`sys_munmap` 以及 `sys_spawn` 的移植过程中，初步沿用了既有章节的地址空间映射及进程生成（ELF 加载）逻辑，并尝试适配新版内核的全局进程数据结构。

## 遭遇的工程阻碍

在执行验证测试与自动化检测程序时，系统出现了多项致命错误，研发陷入停滞，具体壁垒如下：

1. **虚拟内存映射边界与返回值规范异常**：在处理 `sys_mmap` 与 `sys_munmap` 系统服务时，频繁触发页表项访问异常与用户程序崩溃。初期的移植版本未充分考虑 `SV39` 虚拟内存架构下的页边界严格对齐（Page-Aligned）规范。在处理非整页长度的用户请求时，映射区间计算错误；同时，未能正确甄别并拒绝重叠区间（Overlap）的映射请求。更为严重的是，原本在其他架构中常见的返回映射虚拟地址的习惯被带入，这违背了本系统 `mmap` 处理成功需返回 `0` 的底层契约。
2. **硬链接计数与块缓存一致性失效**：在执行高频率构建与断开硬链接的并发测试场景下，底层磁盘索引节点（`DiskInode`）发生资源泄漏。在原先的 `unlink` 逻辑中，虽然内存状态下的 `nlink` 属性被正确递减，但未能通过块缓存（Block Cache）机制标记相关数据结构对应的扇区为“脏扇区”（Dirty）。此缺失导致底层磁盘元数据未能同步，进而无法触发挥发性数据的物理擦除与回收判定，致使后续分配陷入只增不减的失控状态。

## 用户代码审查与技术指导

在遭遇上述技术架构障碍且排查受阻的情况下，用户适时介入并对具体代码实施了严谨的审查，点出了实现层面的关键缺失。

基于用户的明确指导，我们执行了如下针对性重构：
1. **强化内存映射安全约束**：用户通过查验 `sys_mmap` 流程，指出返回值规范的错误并要求增加重叠访问阻断算法。根据此指导，重构了 `AddressSpace` 层级的地址分配函数逻辑，严格约束地址起始端点必须对齐至 4KB；在正式映射前执行全区间扫描，确保当前指令申请的段域与已有逻辑段不发生任何地址坐标交叉；并修正了映射成功后的正确系统返回码 `0`，彻底消除了内存覆盖与页错误陷阱。
2. **修补块缓存底层数据同步机制**：针对资源回收失效的问题，用户查明了是由于文件底层节点释放动作缺乏显式的脏页通告所致。依据指导，我们在 `Inode::unlink` 和资源删除调用周期的末端，强制引入了对当前获取的磁盘块缓冲区的修改标记方法（`modify` 同步函数），确保 `nlink` 减少至 `0` 时的清空动作必然进入缓存池刷新队列。由此确保了存储层元数据的一致性落盘。

## 结论

本章系统调用的高安全性跨越得益于用户及时、精准的架构层指引。通过强制执行虚拟内存边界对齐算法及重整页数据结构的缓存同步时序，此前遗留的隐患已被全域肃清。经过修复与编译组合后的内核，在 ./test.sh all 工作流的压测下稳定并高效地通过了全部 33 项文件依赖与内存交织综合测点，系统运行机制完全符合本章架构预设要求。
